# Known problems

Reviewed on 2026-10-29 against the source starting at commit `b600507`. These are findings from code/configuration inspection, not a record of completed runtime tests. Where failure depends on timing, database state, or browser behaviour, that condition is stated explicitly. No hosted deployment currently exists.

## Build and local setup

| Problem | Evidence and impact | Follow-up |
| --- | --- | --- |
| Frontend cannot be installed/built from a fresh checkout | [`Frontend/Boomvox_UI/`](../Frontend/Boomvox_UI/) contains source but no `package.json`, lockfile, `angular.json`, or `tsconfig*.json`. Dependency versions, scripts, targets, and environment replacements are unknown. | Recover the original workspace metadata and commit it; validate install, build, and tests. |
| Native audio tools are external prerequisites | [`AudioProcessingJob`](../Backend/src/main/java/bg/fmi/uni/boomvox/job/AudioProcessingJob.java) invokes FFmpeg/FFprobe. The Maven library does not install them. Missing executables prevent audio processing. | Install both binaries on `PATH` with MP3/AAC encoders and verify processing on the intended host. |
| No initial administrator | [`AuthService`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/AuthService.java) always registers `ORDINARY_USER`; migrations seed no account. Upload/admin features need another role. | Use the documented trusted local DB bootstrap; implement a controlled bootstrap process before hosting. |

## Authentication and access control

These issues should be resolved before exposing the API publicly.

| Problem | Evidence and impact | Follow-up |
| --- | --- | --- |
| Author permissions are declared but not activated | [`LibraryController`](../Backend/src/main/java/bg/fmi/uni/boomvox/controller/LibraryController.java) and [`SongController`](../Backend/src/main/java/bg/fmi/uni/boomvox/controller/SongController.java) use `@PreAuthorize`, but the source has no `@EnableMethodSecurity`. [`SecurityConfig`](../Backend/src/main/java/bg/fmi/uni/boomvox/config/SecurityConfig.java) only enforces the `ADMIN` role on `/api/admin/**`. Other authenticated users are not blocked by those method annotations. | Enable method security, enforce resource ownership on catalogue writes, and test allowed/denied operations. |
| Reset token is returned to an unauthenticated caller | [`AuthController`](../Backend/src/main/java/bg/fmi/uni/boomvox/controller/AuthController.java) exposes forgot-password without authentication, and [`AuthService`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/AuthService.java) returns the account's usable reset token directly. Knowing an email can enable account takeover. | Deliver reset credentials through an out-of-band ownership check and return a generic response to the request. |
| Shared signing secret is committed | [`application.yml`](../Backend/src/main/resources/application.yml) contains the JWT key inherited by profiles unless overridden. A known signing key permits forged tokens. | Supply a unique secret through local/host configuration and rotate any key that has been used outside disposable development. |
| Streaming sessions lack ownership checks | [`StreamingSessionController`](../Backend/src/main/java/bg/fmi/uni/boomvox/controller/StreamingSessionController.java) looks up any supplied session ID; [`PlaybackService`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/PlaybackService.java) updates it without checking the caller. | Resolve sessions by both ID and authenticated user before accepting events or status updates. |
| Refresh/logout assume a principal on permitted paths | `/api/auth/**` is permitted in `SecurityConfig`, but refresh/logout dereference `currentUser`. Anonymous requests can raise a null-principal server error. | Require authentication on those two paths and define a consistent unauthenticated response. |
| JWT identity is tied to mutable username | [`JwtService`](../Backend/src/main/java/bg/fmi/uni/boomvox/security/JwtService.java) stores username as subject; [`CustomUserDetailsService`](../Backend/src/main/java/bg/fmi/uni/boomvox/security/CustomUserDetailsService.java) looks it up on each request. Changing username can break existing-token authentication. | Use an immutable user ID or reissue the session safely after a rename. |
| Token lifecycle is minimal | Backend logout is a no-op. The UI checks only token presence, caches role in local storage, and has no automatic refresh; its interceptor reacts only to 401. | Define expiry, revocation, role-refresh, and rejected-request behaviour across both applications. |

## API and data contracts

| Problem | Evidence and impact | Follow-up |
| --- | --- | --- |
| Custom exceptions are not mapped to HTTP statuses | [`exception/`](../Backend/src/main/java/bg/fmi/uni/boomvox/exception/) contains plain runtime exceptions. There is no controller advice or `@ResponseStatus`; [`ErrorResponse`](../Backend/src/main/java/bg/fmi/uni/boomvox/dto/ErrorResponse.java) is unused. Invalid credentials, missing records, and business validation can return 500. | Add explicit exception/status mapping and a stable error contract; align the UI error handler. |
| Path/body song IDs can disagree | [`EngagementController`](../Backend/src/main/java/bg/fmi/uni/boomvox/controller/EngagementController.java) rating submission and `LibraryController` tag attachment use the body `songId` while accepting another ID in the path. | Use the path ID as authoritative or reject mismatches. |
| Frontend calls missing API operations | [`song.ts`](../Frontend/Boomvox_UI/src/app/services/song.ts) calls `GET /songs/{id}/tags`; [`album.ts`](../Frontend/Boomvox_UI/src/app/services/album.ts) calls `DELETE /albums/{id}`. Neither has a controller mapping. | Implement the required operations or remove their callers. |
| Song update contracts differ | UI `SongRequest` sends name/genre/album ID; backend [`SongRequest`](../Backend/src/main/java/bg/fmi/uni/boomvox/dto/SongRequest.java) requires format/duration/fileSize/storageKey too. [`SongService.updateSong`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/SongService.java) also does not apply the submitted album or format. | Define a metadata-edit contract and implement the same fields on both sides. |
| Albumless upload is inconsistent | Migration 021 makes `album_id` nullable and upload permits null. [`Song`](../Backend/src/main/java/bg/fmi/uni/boomvox/domain/Song.java) still has `@JoinColumn(nullable = false)`. Artist/genre exist only through an album, and the UI's submitted song genre has no backend upload field. | Align JPA/SQL nullability and decide how albumless songs retain author/genre. The current mapping can reject an otherwise accepted upload. |
| Playback enums disagree | UI [`SessionStatus`](../Frontend/Boomvox_UI/src/app/models/enums.ts) uses `INTERRUPTED` on unload/logout; backend uses `ABANDONED`. | Align enums and all session-close callers; incompatible values currently fail JSON deserialisation. |
| Listening-history field differs | UI [`users.ts`](../Frontend/Boomvox_UI/src/app/models/users.ts) and the profile template use `listenedDurationSeconds`; backend [`ListeningHistoryResponse`](../Backend/src/main/java/bg/fmi/uni/boomvox/dto/ListeningHistoryResponse.java) returns `listenedDurationSec`. | Use the backend field consistently; the UI currently displays no value for that property. |
| Other interfaces have drifted | UI lacks `GUEST` and `FLAC`, omits stream duration/quality fields, assumes some nullable IDs are always present, and types song-tag attachment as `TagResponse` instead of `SongTagResponse`. | Reconcile interfaces with the [API reference](project-endpoints.md), preferably with a repeatable contract-generation/check process. |
| Validation is uneven | `LogEventRequest`, `UpdateSessionRequest`, and `AdminPromoteRequest` lack constraints; registration omits DB string-length limits. `@Valid` alone does not add those checks. | Validate required values, ranges, string lengths, and allowed state transitions at the API boundary. |
| Internal and personal fields are broadly returned | [`SongResponse`](../Backend/src/main/java/bg/fmi/uni/boomvox/dto/SongResponse.java) exposes storage keys, including a raw key whose object is deleted after processing. [`UserResponse`](../Backend/src/main/java/bg/fmi/uni/boomvox/dto/UserResponse.java) exposes email in other-user/artist views. | Return fields required by each client view. Storage keys alone do not grant access to a private S3 object. |
| Deletion does not clean relational dependencies | Song and playlist services delete parent rows without removing all dependent rows; SQL foreign keys do not cascade. Song deletion performs S3 deletion before the DB delete. Referenced records can cause the DB operation to fail after files have been removed. | Define relationship cleanup and coordinate object deletion with successful DB changes. |

## Audio and playback

| Problem | Evidence and impact | Follow-up |
| --- | --- | --- |
| Async job can run before upload commit | Transactional `SongService.uploadSong` submits [`AudioProcessingJob`](../Backend/src/main/java/bg/fmi/uni/boomvox/job/AudioProcessingJob.java) before returning. The separate worker transaction can query a song that is not visible yet. This is a timing-dependent failure risk. | Submit after transaction commit and test the upload/worker boundary. |
| Job processing is not durable | Executor queue is in memory; no retry/recovery endpoint or persistent job dispatcher exists. A restart can lose queued/running work. Failed jobs can leave raw or partial variant objects behind. | Add recovery for stuck `PROCESSING` songs, retry semantics, and orphan cleanup. |
| Signed URL expiry has two sources | [`FileStorageService`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/FileStorageService.java) signs for configurable minutes; [`StreamingController`](../Backend/src/main/java/bg/fmi/uni/boomvox/controller/StreamingController.java) reports 15 minutes unconditionally. | Derive the URL and returned expiry from one value; until then keep the default 15. |
| Signed response content type is fixed | The signer forces `audio/mpeg` even though AAC variants exist. Current non-guest selection generally chooses the 320 kbps MP3, but alternate selections can be labelled incorrectly. | Sign using the selected variant's actual MIME type. |
| Playback statistics are incomplete | [`PlaybackService.endSession`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/PlaybackService.java) uses wall-clock duration, including pauses, and does not increment play counts or log `END`. Other collection/recommendation operations also leave their statistics counters unchanged. | Define and maintain counter/event semantics using actual playback activity; test repeated close requests. |
| URL refresh can leave a session open | [`PlayerService.refreshStream`](../Frontend/Boomvox_UI/src/app/services/player.ts) replaces the session ID after requesting another URL, without closing the previous session. | Separate URL renewal from session creation or explicitly end the old session. |
| Unload reporting is unreliable | Player unload handling uses an ordinary async HTTP request, which browsers may cancel during navigation/close; the sent status is also currently invalid. | Align the status, use a delivery mechanism appropriate for unload, and expire stale sessions on the server. |
| Player/poll error handling is limited | Audio `play()` promise failures are unhandled. [`Upload.pollStatus`](../Frontend/Boomvox_UI/src/app/pages/upload/upload.ts) has no timeout or component-destroy cleanup. Player events omit `positionSec` in several calls. | Handle playback failures, bound and clean up polling, and send consistent event positions. |

## Configuration and deployment

| Problem | Evidence and impact | Follow-up |
| --- | --- | --- |
| Production profile is incomplete | [`application-prod.yml`](../Backend/src/main/resources/application-prod.yml) changes logging only. Database/schema and 100 MB multipart settings are in dev, and base port is 8099. Frontend production constants still point to localhost:9090. | Supply prod configuration explicitly and restore frontend build replacement wiring; see [configuration reference](deployment.md#configuration-reference). |
| Browser origin is fixed | [`SecurityConfig`](../Backend/src/main/java/bg/fmi/uni/boomvox/config/SecurityConfig.java) allows only `http://localhost:4200`. | Configure the actual origin when hosting or using another local origin. |
| AI dependency and configuration disagree | POM includes Ollama; dev configuration contains OpenAI settings and commented Ollama settings. No business service uses an AI client. | Remove unused integration or configure one intentional provider if a feature needs it. An API key is not required by the implemented scoring algorithm. |
| AWS credential modes are limited | [`S3Config`](../Backend/src/main/java/bg/fmi/uni/boomvox/config/S3Config.java) builds static basic credentials and ignores session tokens/default-provider roles. | Support the credential mode required by the future host instead of assuming IAM roles work already. |
| Optional secrets filename is not ignored | Spring imports `aws.env`, but [`.gitignore`](../Backend/.gitignore) only ignores `.env`. | Prefer the documented `.env`; ignore any additional secrets file before using it. |
| No operational deployment tooling | No checked-in deployment workflow, infrastructure definition, health endpoint, backup procedure, or worker recovery process exists. | Introduce these with the first hosted environment and record its actual URLs and ownership. |

Recommendation generation also scans all songs and performs repeated tag lookups; large catalogues can produce high memory use and many queries. The current click endpoint only retrieves a recommendation and does not record analytics. These behaviours are visible in [`RecommendationService`](../Backend/src/main/java/bg/fmi/uni/boomvox/service/RecommendationService.java).

## Verification and test coverage

The only backend test is [`BoomvoxApplicationTests.contextLoads`](../Backend/src/test/java/bg/fmi/uni/boomvox/BoomvoxApplicationTests.java). [`TestcontainersConfiguration`](../Backend/src/test/java/bg/fmi/uni/boomvox/TestcontainersConfiguration.java) is an empty class; the container definitions are commented out, so tests do not provision PostgreSQL or other dependencies. The test does not select the `test` profile. Selecting that profile separately lacks an `AppLogger` bean (implementations match only dev/prod) and uses a stale `theatre` property prefix.

Frontend specs contain generated assumptions that disagree with current source: for example [`auth.spec.ts`](../Frontend/Boomvox_UI/src/app/services/auth.spec.ts) imports `Auth` while the service exports `AuthService`, and `app.spec.ts` expects the old generated welcome title. No frontend test runner can be established without restoring workspace metadata.

Documentation checks can verify links, endpoint inventory, and examples against source, but they do not establish runtime correctness. Required follow-up coverage includes role/ownership rejection, HTTP exception mapping, database migration from a clean schema, upload commit/worker timing, S3/FFmpeg processing, playback contract agreement, collection deletion, and recommendation behaviour.
